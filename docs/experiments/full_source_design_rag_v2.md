# Full-Source Design-Knowledge RAG v2

## 変更点

1. 非RAG・RAGの両条件で、対象部分を含むソースファイル全体を設計文書生成LLMへ入力する。
2. 設計文書化およびコード再生成の対象は、設定で指定した関数またはクラスの範囲だけとする。
3. RAG条件では、リポジトリ内コードではなく、対象非依存の汎用詳細設計知識を取得して設計文書生成プロンプトへ追加する。

## 比較条件

### 非RAG

- 入力: 対象を含むソースファイル全体
- 追加知識: なし

### RAG

- 入力: 非RAGと同一のソースファイル全体
- 追加知識: `knowledge/detailed-design/general-v1.md`
- 取得方式: 全対象で同一クエリ、同一知識、対象別調整なし

## 共通固定条件

- 同一のSystemプロンプト
- 同一の基本Userプロンプト
- 同一対象、同一観察ファイル、同一置換範囲
- 同一モデル、生成設定、Docker image、テスト条件
- 設計文書生成・コード再生成は各1回
- retry、自動修復、手修正なし
- コード再生成時に元コードおよびRAG知識を再投入しない
- 旧実験のrun ID・出力先を上書きしない

## 最初のpilot

RISCV-Simulatorの`Register`を用い、次を確認する。

- ソースファイル全体が`design_input.txt`へ保存される
- 設計文書の対象が`Register`だけに限定される
- 非RAGには検索コンテキストがない
- RAGには汎用詳細設計知識が追加される
- 再生成コードは`Register`範囲だけを置換する
- テスト後に元ファイルが復元される
