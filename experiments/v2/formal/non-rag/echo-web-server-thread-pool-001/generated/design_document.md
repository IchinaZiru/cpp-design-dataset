# デザイン文書

## 概要
この設計文書は、`thread_pool.h`と`thread_pool.cpp`を含むスレッドプールモジュールについて記載しています。スレッドプールの公開インターフェース、内部処理フロー、例外処理、依存関係などを詳細に説明します。

## モジュール構造

### ファイル間の関係
- `thread_pool.h`: クラス定義と公開インターフェースを含むヘッダーファイル。
- `thread_pool.cpp`: 実装ファイルで、`ThreadPool`クラスのメンバ関数を定義しています。

## 公開インターフェース

### クラス: `ws::ThreadPool`

#### 責務
スレッドプールを作成し、タスクをスケジューリングして並列に実行します。スレッドのライフサイクル管理とタスクキューの管理を行います。

#### 入力
- スレッド数 (`std::optional<std::size_t>`)
- ロガー (`log::Logger::Ptr`)

#### 出力
なし

#### 状態
- `closed_`: スレッドプールが閉じているかどうかを示すフラグ。
- `tasks_`: タスクキュー。
- `threads_`: スレッドリスト。

#### 公開メソッド

1. **コンストラクタ**
   - `ThreadPool(std::optional<std::size_t> thread_count = std::nullopt, log::Logger::Ptr logger = log::RootLogger()) noexcept`
     - スレッドプールを初期化します。スレッド数とロガーを設定します。

2. **デストラクタ**
   - `~ThreadPool() noexcept`
     - スレッドプールを破棄し、すべてのワーカースレッドが終了するまで待ちます。

3. **コピー・ムーブコンストラクタと代入演算子**
   - コピーとムーブは禁止されています。

4. **スレッドプール開始**
   - `void Start() noexcept`
     - スレッドプールを起動し、指定された数のワーカースレッドを作成します。

5. **タスク追加**
   - `void Push(Task task) noexcept`
     - タスクキューに新しいタスクを追加します。

6. **スレッドプール終了**
   - `void Close() noexcept`
     - スレッドプールを閉じ、未処理のタスクは実行されません。

#### 例外・失敗条件
- タスクの実行中に例外が発生した場合、そのメッセージはロガーに記録されます。
- `Start()`メソッドが呼び出されたときに既にスレッドプールが開始されている場合、アサートが発生します。
- `Push()`メソッドが呼び出されたときにスレッドプールが閉じている場合、アサートが発生します。

#### 依存関係
- `log::Logger`: ロギング機能を提供するクラス。
- `<condition_variable>`, `<functional>`, `<list>`, `<mutex>`, `<optional>`, `<thread>`: C++標準ライブラリのコンポーネントを使用しています。

#### 重要な不変条件
- `closed_`が`true`の場合、タスクキューは空であるべきです。
- スレッドプールが閉じている場合、新しいタスクを追加することはできません。

## 内部処理フロー

### コンストラクタ
1. ロガーの設定: 引数で指定されたロガーを使用するか、デフォルトのグローバルロガーを使用します。
2. スレッド数の決定: 引数で指定されたスレッド数を使用するか、ハードウェアがサポートする並列スレッド数を使用します。

### デストラクタ
1. `Close()`メソッドを呼び出してスレッドプールを閉じます。
2. すべてのワーカースレッドが終了するまで待ちます。

### スレッド開始 (`Start()`)
1. アサート: スレッドプールが既に開始されていることを確認します。
2. `closed_`フラグを`false`に設定します。
3. 指定された数のワーカースレッドを作成し、それぞれ`ExecProc()`メソッドを実行するようにスケジューリングします。

### タスク追加 (`Push(Task task)`)
1. アサート: スレッドプールが閉じていないことを確認します。
2. ロックガードを使用してタスクキューにアクセスします。
3. タスクをタスクキューに追加し、条件変数を通知して待機中のワーカースレッドを起床させます。

### タスク実行 (`ExecProc()`)
1. 条件変数の待機: タスクキューが空でないか、スレッドプールが閉じているかを確認します。
2. タスクキューからタスクを取り出し、ロックガードを使用してタスクキューにアクセスします。
3. タスクを実行し、例外が発生した場合はロガーにエラーメッセージを記録します。

### スレッドプール終了 (`Close()`)
1. ロックガードを使用してスレッドプールの状態にアクセスします。
2. `closed_`フラグを`true`に設定し、条件変数を通知して待機中のワーカースレッドを起床させます。これによりワーカースレッドは終了処理を行います。
