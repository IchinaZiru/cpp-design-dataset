# デザイン文書: heap-timerモジュール

## 概要
この設計文書は、`heap_timer.h`ファイルを基にした再実装のための設計情報を提供します。`HeapTimer`クラスは、最小ヒープを使用してタイマーを管理し、各タイマーが期限切れになったときにコールバック関数を呼び出す機能を提供します。

## ファイル構造
- **heap_timer.h**: `HeapTimer`クラスの定義と実装

## 責務
- タイマーの追加、調整、削除、および期限切れ時のコールバック処理。
- 内部データ構造（最小ヒープ）を維持し、効率的なタイマーマネージメントを行う。

## 公開インターフェース

### コンストラクタ
```cpp
explicit HeapTimer(log::Logger::Ptr logger = log::RootLogger()) noexcept;
```
- **説明**: ロガーを指定して`HeapTimer`オブジェクトを作成します。ロガーが指定されない場合は、グローバルルートロガーを使用します。
- **入力**:
  - `logger`: ロガーへのポインタ（省略可）。

### メソッド
```cpp
void Adjust(const Key& key, Clock::duration expiration);
void Adjust(const Key& key, Clock::time_point expiration);
```
- **説明**: 指定されたキーを持つノードの期限切れ時間を調整します。
- **入力**:
  - `key`: ノードを特定するためのキー。
  - `expiration`: 新しい期限切れ時間（相対的または絶対的）。

```cpp
void Push(const Key& key, Clock::duration expiration, TimeOutCallback callback) noexcept;
void Push(const Key& key, Clock::time_point expiration, TimeOutCallback callback) noexcept;
```
- **説明**: 新しいノードをタイマーシステムに追加します。
- **入力**:
  - `key`: ノードを特定するためのキー。
  - `expiration`: 期限切れ時間（相対的または絶対的）。
  - `callback`: 期限切れ時に呼び出されるコールバック関数。

```cpp
void Tick() noexcept;
```
- **説明**: 期限切れになったノードを削除し、それらのコールバックを呼び出します。例外はロガーに記録されます。

```cpp
bool Remove(const Key& key) noexcept;
```
- **説明**: 指定されたキーを持つノードを削除します。
- **入力**:
  - `key`: 削除するノードのキー。
- **出力**:
  - ノードが削除されたかどうか。

```cpp
void Invoke(const Key& key);
```
- **説明**: 指定されたキーを持つノードを削除し、そのコールバックを呼び出します。例外はロガーに記録されます。
- **入力**:
  - `key`: 削除するノードのキー。

```cpp
Key Pop() noexcept;
```
- **説明**: 最も期限切れが近いノードを削除し、そのキーを返します。タイマーシステムが空である場合、未定義動作となるため呼び出し前に`Empty()`を確認してください。
- **出力**:
  - 削除されたノードのキー。

```cpp
void Clear() noexcept;
```
- **説明**: タイマーシステム内のすべてのノードを削除します。

```cpp
bool Contain(const Key& key) const noexcept;
```
- **説明**: 指定されたキーを持つノードが存在するかどうかを返します。
- **入力**:
  - `key`: 存在確認するノードのキー。
- **出力**:
  - ノードが存在するかどうか。

```cpp
bool Empty() const noexcept;
```
- **説明**: タイマーシステムが空であるかどうかを返します。
- **出力**:
  - タイマーシステムが空であるかどうか。

```cpp
std::size_t Size() const noexcept;
```
- **説明**: タイマーシステム内のノード数を返します。
- **出力**:
  - ノード数。

```cpp
Clock::duration ToNextTick() noexcept;
```
- **説明**: 期限切れになったノードを削除し、次のノードの期限切れまでの間隔を返します。タイマーシステムが空である場合は0を返します。
- **出力**:
  - 次のノードの期限切れまでの間隔。

## 内部構造

### ノード構造
```cpp
struct Node {
    Key key;
    Clock::time_point expiration;
    TimeOutCallback callback;
    bool Expired() const noexcept;
    void Swap(Node&) noexcept;

    friend std::weak_ordering operator<=>(const Node& lhs, const Node& rhs) noexcept;
};
```
- **説明**: タイマーを表すノード構造体。
- **メンバ変数**:
  - `key`: ユニークなキー。
  - `expiration`: 期限切れ時間。
  - `callback`: 期限切れ時に呼び出されるコールバック関数。

### メンバ変数
```cpp
log::Logger::Ptr logger_;
std::unordered_map<Key, std::size_t> key_to_idx_;
std::deque<Node> nodes_;
```
- **説明**: タイマーシステムの内部状態を管理するメンバ変数。
- **詳細**:
  - `logger_`: ロガーへのポインタ。
  - `key_to_idx_`: キーからノードインデックスへのマップ。
  - `nodes_`: ノードを保持するデキュー。

## 処理手順

### Adjust
1. 指定されたキーを持つノードのインデックスを取得します。
2. コールバックが指定されている場合は、そのコールバックを更新します。
3. 新しい期限切れ時間が現在の期限切れ時間よりも早い場合、`ShiftUp`を呼び出します。それ以外の場合、`ShiftDown`を呼び出します。

### Push
1. 指定されたキーを持つノードが既に存在するか確認します。
2. 存在しない場合は、新しいノードを作成し、デキューの末尾に追加します。その後、`ShiftUp`を呼び出してヒーププロパティを維持します。
3. 既存の場合は、`Adjust`メソッドを使用して期限切れ時間を更新します。

### Tick
1. タイマーシステムが空でない限り、最も期限切れが近いノードを確認します。
2. 期限切れである場合、そのノードを削除し、コールバックを呼び出します。例外はロガーに記録されます。
3. 期限切れでない場合は、処理を終了します。

### Remove
1. 指定されたキーを持つノードが存在するか確認します。
2. 存在する場合、`RemoveByIndex`メソッドを使用してノードを削除し、trueを返します。それ以外の場合、falseを返します。

### Invoke
1. 指定されたキーを持つノードのインデックスを取得します。
2. コールバックを呼び出します。例外はロガーに記録されます。
3. ノードを削除します。

### Pop
1. タイマーシステムが空であることを確認します。
2. 最も期限切れが近いノード（ヒープの先頭）を削除し、そのキーを返します。

### Clear
1. デキューとマップをクリアします。

### Contain
1. 指定されたキーを持つノードが存在するか確認します。
2. 存在する場合はtrueを、それ以外の場合はfalseを返します。

### Empty
1. ノードリストが空であることを確認します。
2. 空である場合はtrueを、それ以外の場合はfalseを返します。

### Size
1. ノードリストのサイズを取得します。
2. サイズを返します。

### ToNextTick
1. `Tick`メソッドを使用して期限切れになったノードを削除します。
2. 次のノードの期限切れまでの間隔を計算し、その値を返します。タイマーシステムが空である場合は0を返します。

## 例外・失敗条件
- `Adjust`メソッド: 指定されたキーを持つノードが存在しない場合、`std::out_of_range`例外をスローします。
- `Invoke`メソッド: 指定されたキーを持つノードが存在しない場合、`std::out_of_range`例外をスローします。

## 重要な不変条件
- `nodes_`と`key_to_idx_`は常に同期されている。つまり、`key_to_idx_[key]`が有効なインデックスを指す場合、そのインデックスは`nodes_`内の有効なノードに対応している。
- ヒーププロパティ: `nodes_`は最小ヒープとして維持されている。つまり、親ノードの期限切れ時間が子ノードの期限切れ時間以下である。
