# 汎用詳細設計知識 v2

## 目的

対象コードから、再実装に必要な構造、インターフェース、状態、依存関係、処理順序を失わない詳細設計文書を作成する。
この知識で指定する成果物は、元の記載項目に追加する必須成果物として扱う。

## 0. 根拠と正確性の共通規則

- 元コードで確認できる事実だけを記述する。
- 対象部分以外のコードは、対象部分との関係を説明するためにのみ使用する。
- 元コードに登場しない呼び出し元、管理機構、利用場面、例外、制約を作らない。
- 型名、引数名、メンバ名、関数名、条件式、比較演算子、代入先、更新順序は元コードの表記に合わせる。
- 確認できない情報は推測せず「確認できない」と記述する。
- 対象に該当しない成果物は省略せず、「該当なし」とコード上の判断根拠を記述する。
- 「依存関係なし」とする前に、継承元、テンプレート型、引数型、戻り値型、メンバ型、呼び出し関数、定数、列挙型、型別名を確認する。
- 「エラー処理なし」ではなく、元コードにない場合は「明示的なエラー処理は確認できない」と記述する。
- 前提条件、事後条件、状態変更、不変条件を混同しない。
  - 前提条件: 呼び出し前に成立が必要な条件。
  - 事後条件: 呼び出し完了後に保証される条件。
  - 状態変更: 処理によって変更される値や外部資源。
  - 不変条件: 処理の前後を通じて維持される条件。

## 1. 概要と責務

対象の責務と対象範囲を簡潔に記述する。
元コードから確認できない上位システムの目的や実行タイミングは追加しない。

## 2. 構造図

クラスまたは構造体が対象、あるいは対象に直接関係する場合は、Markdown内にMermaid `classDiagram`を必ず出力する。
最低限、確認できる範囲で次を含める。

- クラス名・構造体名
- 継承関係
- 属性名、型、可視性
- 公開メソッドのシグネチャ
- 直接確認できる依存、所有、参照関係

単独関数でクラス構造が関係しない場合は、「該当なし」とその根拠を記述する。

## 3. インターフェースと依存関係

対象の各クラス、関数、メソッドについて、次を表形式または箇条書きで記述する。

- 完全な名前
- 引数名、型、意味
- 戻り値の型と意味
- `const`、参照、ポインタ、`noexcept`、`virtual`などの修飾
- 使用するメンバ、型、定数、列挙型、型別名
- 呼び出す関数・メソッドとその目的
- 継承元、テンプレート型などの直接依存

公開インターフェースと実装上の処理を分けて記述する。

## 4. 処理フロー図

Markdown内にMermaid `flowchart`を必ず1つ以上出力する。

- 単独関数対象では、対象関数の開始から終了までを表す。
- クラス対象では、分岐、反復、状態変更、早期終了のいずれかを含む主要メソッドを対象にする。
- 複数ファイル対象では、主要な公開処理または主要な状態遷移を対象にする。
- クラス内に複雑な処理がない場合も、最も重要な状態更新または値の受け渡しを図示する。
- 条件分岐では条件式と分岐後の処理を明記する。
- 状態変更では更新対象、代入元、更新順序を明記する。
- 早期終了や処理を行わない分岐も省略しない。

図のノードやエッジに、元コードで確認できない外部の呼び出し元を追加しない。

## 5. シーケンス図

対象コードから複数の関数、メソッド、オブジェクト間の呼び出し順序を直接確認できる場合は、Markdown内にMermaid `sequenceDiagram`を出力する。
次を確認できる範囲で含める。

- 呼び出す側と呼び出される側
- 呼び出す関数・メソッド
- 渡す値
- 戻り値の利用
- 状態更新の順序
- 条件分岐、早期終了、エラー経路

相互作用を確認できない場合は、架空の参加者を作らず、「該当なし」とその根拠を記述する。

## 6. 関数・メソッド仕様書

対象関数または主要メソッドについて、最低限次の項目を表形式で記述する。

| 項目 | 記述内容 |
|---|---|
| 完全な名前 | 名前空間、クラス名を含む対象名 |
| 目的 | 元コードから確認できる責務 |
| 引数 | 名前、型、意味、確認できる許容範囲・特別値 |
| 戻り値 | 型、意味、値ごとの条件 |
| 前提条件 | 呼び出し前に必要だとコードから確認できる条件 |
| 事後条件 | 正常終了後に保証される条件 |
| 動作の説明 | 分岐、反復、計算、呼び出し、更新の順序 |
| 状態変更・副作用 | メンバ、引数先、外部資源への変更 |
| 依存関係 | 使用する型、関数、定数、外部状態 |
| 境界条件 | 空、0、最大・最小、終端、範囲外などの扱い |
| エラー処理 | 例外、エラー値、無視、早期終了、または明示的処理が確認できないこと |
| 不変条件 | 処理の前後を通じて維持される条件 |

単純なgetterやsetterも省略せず、事実に基づいて簡潔に記述する。

## 7. 状態遷移と重要な条件

状態を保持する対象では、次を明記する。

- 更新前の状態
- 更新条件
- 更新対象と更新値
- 更新されない条件
- 更新順序
- 処理後に成立する条件

数値、比較演算子、境界値、条件式を自然言語だけで曖昧にしない。

## 8. 確認不能事項

設計文書の末尾に、元コードだけでは確認できなかった情報を列挙する。
確認不能事項がない場合は「確認不能事項なし」と記述する。
