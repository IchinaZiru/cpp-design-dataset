最終設計仕様書に記載された置換unitをC++コードとして再生成してください。

規則:
- 設計仕様書に記載された名前、型、signature、namespace、修飾子を変更しないでください。
- C++としてコンパイル可能なコードを生成してください。
- 設計仕様書に存在しない型、API、ファイル、unitを勝手に作らないでください。
- `replacement_required=true`と記載された置換unitだけを生成し、参照専用unitは生成しないでください。
- 各`content`には指定された置換unit本体だけを含めてください。function/byte-span unitでは周辺の`#include`、namespace wrapper、既存の定数・型・helper定義、別unitを複製しないでください。full-file/module-file unitでは`#include`、namespace、型、inline実装を含むファイル全体がunit本体であり、この除外規則の対象外です。
- function置換unitの`content`には、戻り値型、完全な関数名、引数list、修飾子、開閉波括弧、関数bodyを含む完全な関数定義を出力してください。関数body内の文だけを出力してはいけません。
- full-fileまたはmodule-file置換unitの`content`には、設計仕様書に記載された完全なファイルを先頭から末尾まで出力してください。include guardまたはpragma、必要なinclude、namespace、using、すべての型宣言、すべてのメンバー、すべてのinline実装、終端を省略してはいけません。代表的な関数一つ、宣言だけ、またはファイルの一部分だけを出力してはいけません。
- 設計仕様書で既存の周辺symbolとして示されたものは利用だけ行い、再定義しないでください。
- 設計仕様書に記載された変数型、初期値、条件式、比較演算子、分岐順序、更新順序、戻り値、error path、境界条件を逐語的に実装し、省略や等価な書き換えをしないでください。
- 設計仕様書で内容が確認不能とされた定数、table、型、APIを推測して作成しないでください。
- 出力前に、設計仕様書に列挙されたすべての正常経路・異常経路・終了条件が生成コードに存在することを内部確認してください。
- 指定されたJSON Schemaへ厳密に従ってください。
- JSON以外の説明やMarkdownを出力しないでください。
- C++記号をHTML entity化しないでください。
- 文字列、文字リテラル、template、concept、requiresを正しいC++構文で生成してください。

# ロギングライブラリの設計仕様書

## 概要
このロギングライブラリは、C++で実装された高度なロギングシステムです。以下の主要コンポーネントから構成されています：
- **Logger**: ログを管理するクラス。
- **Appender**: ログ出力先（標準出力、ファイルなど）を定義するクラス。
- **Formatter**: ログメッセージのフォーマットを制御するクラス。
- **Event**: ログイベントを表すクラス。
- **Manager**: 複数のロガーを管理するクラス。

## 1. `log.h` (F01/U01)
### 役割
このファイルは、ロギングライブラリの主要なヘッダーファイルです。クラス定義、列挙型、および関数宣言を含みます。

### 主要コンポーネント

#### 列挙型
- **`Level`**: ログレベルを表す列挙型。
  - `Debug`, `Info`, `Warn`, `Error`, `Fatal`
- **`AppenderType`**: アペンダーの種類を表す列挙型。
  - `StdOut`, `File`

#### 関数
- **`LevelToString`**, **`to_string`**, **`operator<<`**: ログレベルを文字列に変換する関数。
- **`StringToLevel`**: 文字列からログレベルを取得する関数。
- **`AppenderTypeToString`**, **`to_string`**, **`operator<<`**: アペンダーの種類を文字列に変換する関数。
- **`StringToAppenderType`**: 文字列からアペンダーの種類を取得する関数。

#### クラス
1. **`Event`**
   - ログイベントを表すクラス。
   - `Create`メソッドでインスタンスを生成します。
   - メッセージ、ファイル名、行番号、スレッドID、タイムスタンプなどの情報を含みます。

2. **`Formatter::Field`**
   - ログフォーマットのフィールドを表す抽象クラス。
   - `Format`メソッドで出力ストリームにフォーマットされた内容を書き込みます。
   - `Tag`メソッドでフィールドのタグを取得します。

3. **`Formatter`**
   - ログフォーマットパターンを管理するクラス。
   - `Default`メソッドでデフォルトのフォーマッターを取得します。
   - `Format`メソッドでイベントをフォーマットした文字列を生成します。

4. **`Appender`**
   - ログ出力先を定義する抽象クラス。
   - `Log`メソッドでログを出力します。
   - `ToYamlString`メソッドで設定情報をYAML形式の文字列に変換します。

5. **`StdOutAppender`**, **`FileAppender`**
   - 標準出力とファイルへの出力を実装したアペンダークラスです。

6. **`Logger`**
   - ログを管理するクラス。
   - `Log`メソッドでログイベントを処理します。
   - アペンダーの追加、削除、クリアが可能です。
   - 非同期ロギングもサポートしています。

7. **`EventWriter`**
   - ログイベントを書き込むためのラッパークラス。
   - `MessageStream`メソッドでメッセージストリームにアクセスできます。

8. **`Manager`**
   - 複数のロガーを管理するクラス。
   - `FindLogger`メソッドで指定した名前のロガーを取得します。
   - `ToYamlString`メソッドで設定情報をYAML形式の文字列に変換します。

#### グローバル関数
- **`Log`**, **`operator<<`**: ログを出力するための関数。
- **`RootManager`**, **`RootLogger`**, **`FindLogger`**: ルートマネージャーやロガーにアクセスするための関数。

## 設計上の注意点
1. **スレッドセーフ性**: ロギングライブラリはスレッドセーフに設計されており、`std::mutex`を使用して同期を行います。
2. **非同期ロギング**: `Logger`クラスは、キャパシティが設定されている場合、非同期でログを処理します。
3. **フォーマットパターン**: フォーマットパターンは `%d`, `%p`, `%t`, `%m` などのタグを含むことができます。
4. **YAML出力**: 設定情報はYAML形式で出力できるように設計されています。
