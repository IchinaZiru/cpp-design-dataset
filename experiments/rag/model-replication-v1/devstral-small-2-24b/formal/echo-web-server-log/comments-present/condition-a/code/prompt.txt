最終設計仕様書に記載された置換unitをC++コードとして再生成してください。

規則:
- 設計仕様書に記載された名前、型、signature、namespace、修飾子を変更しないでください。
- C++としてコンパイル可能なコードを生成してください。
- 設計仕様書に存在しない型、API、ファイル、unitを勝手に作らないでください。
- `replacement_required=true`と記載された置換unitだけを生成し、参照専用unitは生成しないでください。
- 各`content`には指定された置換unit本体だけを含めてください。function/byte-span unitでは周辺の`#include`、namespace wrapper、既存の定数・型・helper定義、別unitを複製しないでください。full-file/module-file unitでは`#include`、namespace、型、inline実装を含むファイル全体がunit本体であり、この除外規則の対象外です。
- function置換unitの`content`には、戻り値型、完全な関数名、引数list、修飾子、開閉波括弧、関数bodyを含む完全な関数定義を出力してください。関数body内の文だけを出力してはいけません。
- full-fileまたはmodule-file置換unitの`content`には、設計仕様書に記載された完全なファイルを先頭から末尾まで出力してください。include guardまたはpragma、必要なinclude、namespace、using、すべての型宣言、すべてのメンバー、すべてのinline実装、終端を省略してはいけません。代表的な関数一つ、宣言だけ、またはファイルの一部分だけを出力してはいけません。
- 設計仕様書で既存の周辺symbolとして示されたものは利用だけ行い、再定義しないでください。
- 設計仕様書に記載された変数型、初期値、条件式、比較演算子、分岐順序、更新順序、戻り値、error path、境界条件を逐語的に実装し、省略や等価な書き換えをしないでください。
- 設計仕様書で内容が確認不能とされた定数、table、型、APIを推測して作成しないでください。
- 出力前に、設計仕様書に列挙されたすべての正常経路・異常経路・終了条件が生成コードに存在することを内部確認してください。
- 指定されたJSON Schemaへ厳密に従ってください。
- JSON以外の説明やMarkdownを出力しないでください。
- C++記号をHTML entity化しないでください。
- 文字列、文字リテラル、template、concept、requiresを正しいC++構文で生成してください。

# ロギングシステムの設計仕様書

## 概要
この設計仕様書は、C++で実装されたロギングシステムの詳細な仕様を記述します。このシステムは、イベントのログ記録、フォーマット、および出力先（標準出力やファイル）への書き込みを行います。

## 1. コンポーネント構成
### 1.1 メインクラス
- **Logger**: ロギング機能を提供するメインコンポーネント。アペンダー（出力先）の管理や、同期/非同期処理を行います。
- **Event**: ログイベントを表すクラス。メッセージ、レベル、スレッドID、タイムスタンプなどを含みます。
- **Formatter**: イベントをフォーマットするためのクラス。パターンに基づいて出力形式を決定します。
- **Appender**: ログイベントを特定の場所（標準出力やファイル）に書き込むための抽象クラス。
  - **StdOutAppender**: 標準出力にログを書き込みます。
  - **FileAppender**: ファイルにログを書き込みます。
- **Manager**: 複数のLoggerを管理するクラス。設定の読み込みや変更も行います。

### 1.2 サブコンポーネント
- **Field**: Formatter内で使用されるサブフォーマッター。メッセージ、レベル、スレッドIDなどの個別フィールドをフォーマットします。
- **EventWriter**: イベントを自動的に書き込むためのヘルパークラス。

## 2. クラスとインターフェースの仕様
### 2.1 Logger
#### 機能
- ログイベントの受け取りと処理（同期/非同期）。
- アペンダーの追加・削除。
- デフォルトフォーマッターの設定。

#### メソッド
| メソッド名 | 戻り値 | 引数 | 説明 |
|------------|--------|------|------|
| `Log` | `void` | `Event::Ptr event` | ログイベントを処理します。 |
| `AddAppender` | `void` | `Appender::Ptr appender` | アペンダーを追加します。 |
| `RemoveAppender` | `void` | `Appender::Ptr appender` | アペンダーを削除します。 |
| `SetDefaultFormatter` | `void` | `Formatter::Ptr formatter` | デフォルトのフォーマッターを設定します。 |

### 2.2 Event
#### 機能
- ログイベントの情報（メッセージ、レベル、スレッドIDなど）を保持します。
- メッセージストリームへの書き込みをサポートします。

#### メソッド
| メソッド名 | 戻り値 | 引数 | 説明 |
|------------|--------|------|------|
| `Create` | `Event::Ptr` | `Level level`, `source_location location`, `uint32_t thread_id`, `time_point time` | イベントを作成します。 |
| `MessageStream` | `ostringstream&` | - | メッセージストリームを取得します。 |

### 2.3 Formatter
#### 機能
- パターンに基づいてイベントをフォーマットします。
- サブフォーマッター（Field）の管理を行います。

#### メソッド
| メソッド名 | 戻り値 | 引数 | 説明 |
|------------|--------|------|------|
| `Format` | `string` | `Logger& logger`, `Event& event` | イベントをフォーマットします。 |

### 2.4 Appender
#### 機能
- ログイベントを特定の場所に書き込みます。
- フォーマッターの設定を行います。

#### メソッド
| メソッド名 | 戻り値 | 引数 | 説明 |
|------------|--------|------|------|
| `Log` | `void` | `Logger& logger`, `Event& event` | イベントを書き込みます。 |

### 2.5 Field
#### 機能
- 個別のフィールド（メッセージ、レベルなど）をフォーマットします。

#### メソッド
| メソッド名 | 戻り値 | 引数 | 説明 |
|------------|--------|------|------|
| `Format` | `void` | `ostream& out`, `Logger& logger`, `Event& event` | フィールドをフォーマットします。 |

## 3. 設定管理
### 3.1 YAML形式の設定
- ロガー、アペンダー、フォーマッターの設定をYAMLで記述します。
- 例:
```yaml
loggers:
  - name: root
    level: info
    capacity: 50
    appenders:
      - type: stdout
      - type: file
        file: log.txt
```

### 3.2 設定の読み込みと反映
- `Manager`クラスが設定を読み込み、ロガーの設定を更新します。
- `SetListener`メソッドで設定変更時のコールバックを登録します。

## 4. 使用例
```cpp
// ロガーの作成
auto logger = ws::log::RootLogger();

// イベントの作成とログ記録
ws::log::EventWriter {logger, ws::log::Event::Create(ws::log::Level::Info)}
    .MessageStream() << "Hello, world!";
```

## 5. 注意事項
- `std::experimental::source_location`は将来的に`std::source_location`に置き換えられます。
- 非同期モードでは、イベントキューのキャパシティを指定する必要があります。
