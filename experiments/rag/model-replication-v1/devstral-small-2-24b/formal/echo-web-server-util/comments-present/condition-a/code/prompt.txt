最終設計仕様書に記載された置換unitをC++コードとして再生成してください。

規則:
- 設計仕様書に記載された名前、型、signature、namespace、修飾子を変更しないでください。
- C++としてコンパイル可能なコードを生成してください。
- 設計仕様書に存在しない型、API、ファイル、unitを勝手に作らないでください。
- `replacement_required=true`と記載された置換unitだけを生成し、参照専用unitは生成しないでください。
- 各`content`には指定された置換unit本体だけを含めてください。function/byte-span unitでは周辺の`#include`、namespace wrapper、既存の定数・型・helper定義、別unitを複製しないでください。full-file/module-file unitでは`#include`、namespace、型、inline実装を含むファイル全体がunit本体であり、この除外規則の対象外です。
- function置換unitの`content`には、戻り値型、完全な関数名、引数list、修飾子、開閉波括弧、関数bodyを含む完全な関数定義を出力してください。関数body内の文だけを出力してはいけません。
- full-fileまたはmodule-file置換unitの`content`には、設計仕様書に記載された完全なファイルを先頭から末尾まで出力してください。include guardまたはpragma、必要なinclude、namespace、using、すべての型宣言、すべてのメンバー、すべてのinline実装、終端を省略してはいけません。代表的な関数一つ、宣言だけ、またはファイルの一部分だけを出力してはいけません。
- 設計仕様書で既存の周辺symbolとして示されたものは利用だけ行い、再定義しないでください。
- 設計仕様書に記載された変数型、初期値、条件式、比較演算子、分岐順序、更新順序、戻り値、error path、境界条件を逐語的に実装し、省略や等価な書き換えをしないでください。
- 設計仕様書で内容が確認不能とされた定数、table、型、APIを推測して作成しないでください。
- 出力前に、設計仕様書に列挙されたすべての正常経路・異常経路・終了条件が生成コードに存在することを内部確認してください。
- 指定されたJSON Schemaへ厳密に従ってください。
- JSON以外の説明やMarkdownを出力しないでください。
- C++記号をHTML entity化しないでください。
- 文字列、文字リテラル、template、concept、requiresを正しいC++構文で生成してください。

FINAL_DESIGN_SPECIFICATION:
以下は、与えられたC++ソースコードを解析し、別のLLMが再実装できるように設計仕様書を作成したものです。この仕様書では、入力から確認できない情報は推測せず、Fxx/Uxx識別子や名前空間などの構造を保持しています。

# 設計仕様書

## 1. 概要
この仕様書は、`util.h`と`util.cpp`からなるユーティリティライブラリの再実装のための設計仕様です。このライブラリには、文字列操作、YAMLパース、ファイルディスクリプタ操作、スレッドID取得、バックトレース取得、シンギルトンパターン、RAII管理などの機能が含まれています。

## 2. 名前空間
すべての関数とクラスは`ws`名前空間内に定義されます。

```cpp
namespace ws {
    // 関数とクラスの定義
}
```

## 3. 型定義
### FileDescriptor
ファイルディスクリプタを表す型です。`int`型を使用します。

```cpp
using FileDescriptor = int;
```

### invalid_file_descriptor
無効なファイルディスクリプタを表す定数です。

```cpp
inline constexpr FileDescriptor invalid_file_descriptor {-1};
```

## 5. クラス仕様

### Singleton
シンギルトンパターンの実装です。参照を返します。

```cpp
template <typename T, typename... Args>
class Singleton {
public:
    template <Args... args>
    static T& Instance() noexcept;
};
```

### SingletonPtr
シンギルトンパターンの実装です。スマートポインタを返します。

```cpp
template <typename T, typename... Args>
class SingletonPtr {
public:
    template <Args... args>
    static std::shared_ptr<T> Instance() noexcept;
};
```

### RAII
リソース管理のためのRAIIクラスです。

```cpp
template <typename T, typename Cleaner = std::function<void(T)>>
requires std::is_invocable_v<Cleaner, T>
class RAII {
public:
    explicit RAII(T obj, Cleaner cleaner) noexcept;
    ~RAII() noexcept;
    const T& Object() const noexcept;
private:
    T obj_;
    Cleaner cleaner_;
};
```

### MappedReadOnlyFile
ファイルをメモリにマップするためのRAIIクラスです。

```cpp
class MappedReadOnlyFile {
public:
    MappedReadOnlyFile() noexcept;
    ~MappedReadOnlyFile() noexcept;
    std::byte* Map(std::string path);
    void Unmap() noexcept;
    std::size_t Size() const noexcept;
    std::byte* Data() const noexcept;
    std::string_view Path() const noexcept;
private:
    void Check();
    std::string path_;
    struct stat stat_ {};
    std::byte* data_ {nullptr};
};
```

## 6. コンセプト
### Addable
二つの型が加算可能かを確認するコンセプトです。

```cpp
template <typename T, typename U, typename Ret = T>
concept Addable = requires(T t, U u) {
    { t + u } -> std::convertible_to<Ret>;
};
```
