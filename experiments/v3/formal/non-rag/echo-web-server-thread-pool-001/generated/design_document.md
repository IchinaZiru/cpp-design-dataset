# 設計文書

## 責務
`ThreadPool`クラスは、与えられたタスクを並列に実行するためのスレッドプールを提供します。スレッド数はハードウェアがサポートする並列スレッド数に基づいて設定することも可能です。

## 公開インターフェース
- `ThreadPool(std::optional<std::size_t> thread_count = std::nullopt, log::Logger::Ptr logger = log::RootLogger()) noexcept`: スレッドプールを初期化します。
- `~ThreadPool() noexcept`: スレッドプールを破棄し、すべてのスレッドが終了するまで待ちます。
- `void Start() noexcept`: スレッドプールを開始します。
- `void Push(Task task) noexcept`: タスクキューにタスクを追加します。
- `void Close() noexcept`: スレッドプールを閉じ、未処理のタスクは実行されません。

## 入力
- `thread_count`: スレッド数（省略または0の場合、ハードウェアがサポートする並列スレッド数を使用）。
- `logger`: ロガーインスタンス（省略された場合、グローバルルートロガーを使用）。
- `task`: 実行すべきタスク。

## 出力
- なし

## 状態
- `closed_`: スレッドプールが閉じているかどうかを示すフラグ。
- `thread_count_`: スレッド数。
- `tasks_`: タスクキュー。
- `threads_`: スレッドリスト。

## 処理手順
1. **初期化**: コンストラクタでスレッドプールの設定を行います。スレッド数が指定されていない場合は、ハードウェアの並列スレッド数を使用します。
2. **開始**: `Start()`メソッドを呼び出すと、指定された数のワーカースレッドが生成され、タスクキューからタスクを取り出して実行します。
3. **タスク追加**: `Push(Task task)`メソッドでタスクキューにタスクを追加できます。タスクが追加されると、待機中のワーカースレッドのいずれかが通知を受け取ります。
4. **タスク実行**: ワーカースレッドは`ExecProc()`メソッド内でタスクキューからタスクを取り出して実行します。タスクの実行中に例外が発生した場合は、ロガーにエラーメッセージを記録します。
5. **終了**: `Close()`メソッドでスレッドプールを閉じると、ワーカースレッドはタスクキューからタスクを取り出さなくなります。すべてのワーカースレッドが終了するまで、デストラクタは待機します。

## 例外・失敗条件
- タスク実行中に例外が発生した場合、その例外はキャッチされ、ロガーにエラーメッセージが出力されます。
- `Push()`メソッドを呼び出したときにスレッドプールが閉じていると、アサーションが失敗します。

## 依存関係
- `log::Logger`: ロギング機能を提供するクラス。
- `<condition_variable>`, `<functional>`, `<list>`, `<mutex>`, `<optional>`, `<thread>`: C++標準ライブラリのコンポーネントを使用しています。

## 重要な不変条件
- `closed_`が`true`の場合、タスクキューに新しいタスクを追加することはできません。
- スレッドプールが閉じられると、すべてのワーカースレッドは終了するまで待機します。
