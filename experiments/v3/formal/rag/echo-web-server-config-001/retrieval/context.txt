# 汎用詳細設計知識 v3

## 目的

対象コードから、再実装に有用な詳細設計情報を、一般的なソフトウェア設計の観点で追加生成する。
ここで指定する成果物は、基本9項目を置き換えず、その後に追加する必須成果物として扱う。

## 共通記述規則

- 元コードから確認できる事実だけを記述する。
- 元コードにない機能、利用場面、呼び出し元、例外、依存関係、制約を推測で追加しない。
- 基本9項目と同じ説明を長文で繰り返さず、追加成果物では構造・関係・順序・制約を具体化する。
- 型名、関数名、メソッド名、引数名、メンバ名、条件式、比較演算子などは、確認できる範囲で元コードの表記を保つ。
- 対象に該当しない成果物は省略せず「該当なし」と簡潔な根拠を記述する。
- 確認できない情報は推測せず「確認不能」と記述する。
- 図はMarkdown内のMermaidで記述する。
- 表や図を優先し、冗長な自然言語説明を避ける。

### クラス図

クラス、構造体、インターフェース相当の型が対象または対象に直接関係する場合、Mermaid `classDiagram` を出力する。
確認できる範囲で、クラス・構造体、属性、主要メソッド、継承、所有・参照・直接依存関係を表す。

### クラス・メソッド・インターフェース詳細

対象のクラス、構造体、関数、メソッドについて、再実装に必要なインターフェース情報を表形式で記述する。
確認できる範囲で、完全な名前、属性、引数名と型、戻り値型、可視性、`const`、参照、ポインタ、`static`、`virtual`、`noexcept`、型別名、列挙型、定数、直接依存を含める。

### シーケンス図

複数の関数、メソッド、オブジェクト間の相互作用を元コードから確認できる場合、Mermaid `sequenceDiagram` を出力する。
呼び出し順序、受け渡す値、戻り値の利用、条件分岐、状態変更、エラー経路のうち確認できるものを表す。
相互作用を確認できない場合は「該当なし」とする。

### メソッド仕様書

対象関数または主要メソッドについて、表形式で仕様を記述する。
最低限、メソッド名または完全な関数名、目的、引数、戻り値、動作の説明、副作用、使用例、エラー処理を含める。
使用例は元コード上の利用方法を確認できる場合のみ記述し、確認できない場合は「確認不能」とする。
必要に応じて前提条件、事後条件、境界条件、不変条件も記述する。

### 処理フロー図

主要な処理についてMermaid `flowchart` を出力する。
分岐、反復、早期終了、主要な呼び出し、状態更新、処理順序を確認できる範囲で表す。
単純な処理では過度に細分化せず、再実装に必要な制御の流れを優先する。

### 状態遷移・副作用

状態を保持または変更する処理について、更新前状態、遷移条件、変更対象、更新後状態、更新順序、外部資源への副作用を表形式で記述する。
リソース取得・解放、並行処理上の制約、所有・寿命などが存在する場合は、それらも確認できる範囲で記述する。
状態を持たない対象では「該当なし」とする。

### データ変換・制約

データの変換や値に関する制約を表形式で記述する。
確認できる範囲で、入力形式から出力形式への変換、型変換、加工規則、値域、境界値、単位、精度、エンコーディング、検証条件、特殊値・欠損値の扱いを含める。
言語・ドメイン固有の事項（例: bit幅、符号、byte数、アドレス増分）が存在する場合は、この一般項目の具体例として記述する。
