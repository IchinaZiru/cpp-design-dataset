# 汎用詳細設計知識 v1

## 目的

詳細設計文書は、対象コードの構造、インターフェース、データ構造、処理の流れを、再実装に利用できる粒度で明確にする。
異なる実装者が同じ設計文書を参照したときに、同様の振る舞いを持つ実装を作れることを目標とする。

参考観点: https://zenn.dev/nyanchu/articles/27a3f95d98df45

## 共通ルール

- 元コードに存在する事実だけを記述する。
- 対象部分以外のコードは、対象部分との関係を説明するためにのみ使用する。
- 型、引数、戻り値、状態変更、呼び出し順序、分岐条件、境界条件を省略しない。
- 数値、比較演算子、更新順序、エラー時の動作を可能な限り具体的に記述する。
- 情報が確認できない場合は推測せず「確認できない」と記述する。
- 対象に該当しない成果物は、架空の構造を作らず「該当なし」とする。

## 1. クラス図に相当する構造情報

対象にクラスまたは構造体が関係する場合、次を記述する。

- クラス名・構造体名
- 継承関係
- 保持する属性と型
- 属性の可視性
- 対象メソッドとの関係
- 他クラスとの依存、所有、参照関係

図を作成する場合は、Markdown内のMermaid `classDiagram`形式を使用する。
対象が単独関数で、クラス構造が関係しない場合は「該当なし」とする。

## 2. クラス・メソッド・インターフェースの詳細

対象部分に関係する各要素について、次を表形式または箇条書きで記述する。

- 完全な名前
- 引数名と型
- 戻り値の型
- `const`、参照、ポインタ、例外指定などの修飾
- 呼び出し側が満たす前提条件
- 呼び出し後に保証される事後条件
- 使用する属性、定数、列挙型、型別名
- 呼び出す関数・メソッドと、その目的

インターフェースと実装上の処理を分けて記述する。

## 3. シーケンス図に相当する処理順序

対象部分の実行に複数の関数、オブジェクト、状態が関係する場合、次を時系列で記述する。

- 呼び出し元
- 対象部分
- 呼び出される関数・メソッド
- 引数として渡す値
- 戻り値の利用方法
- 状態更新の順序
- 条件分岐と早期終了
- エラー発生時の処理

図を作成する場合は、Markdown内のMermaid `sequenceDiagram`形式を使用する。
単一処理で相互作用がない場合も、処理手順を番号付きで記述する。

## 4. メソッド仕様書

対象関数またはメソッドについて、最低限次の項目を記述する。

| 項目 | 記述内容 |
|---|---|
| メソッド名 | 完全修飾名を含む対象名 |
| 目的 | この処理が担う責務 |
| 引数 | 名前、型、意味、許容範囲、特別な値 |
| 戻り値 | 型、意味、値ごとの条件 |
| 前提条件 | 呼び出し前に成立している条件 |
| 動作の説明 | 分岐、反復、計算、呼び出し順序を含む処理 |
| 状態変更・副作用 | メンバ、引数先、外部資源への変更 |
| 依存関係 | 使用する型、関数、定数、外部状態 |
| 境界条件 | 空、0、最大値、最小値、終端などの扱い |
| エラー処理 | 例外、エラー値、無視、早期終了など |
| 不変条件 | 処理前後を通じて維持される条件 |

再実装時に解釈が分かれやすい箇所は、自然言語だけで曖昧にせず、条件式、値、順序を明記する。
